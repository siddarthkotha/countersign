# Seat: Gemini (pasted 2026-09-01)

## 1. DEPTH
The verdict is baked into the seed: if SSO location and the out-of-band push are hardcoded to fail for the CEO persona, the caller's fate is predetermined. "You just wrote an IVR that waits 60 seconds to read a hardcoded 'fail' from a mock file." To prove the conversational engine does something, live evidence must OVERRIDE a positive technical signal: a scenario where SSO is active and the OOB push is APPROVED (compromised device or SIM swap) but the engine still freezes because the caller fails cross-turn consistency or falls for a trap. Ranking: 1 story ledger (mandatory); 2 adaptive challenge; 3 stalling library (UX); 4 adversarial corpus (judges won't look at the test suite); 5 timing signals (too fragile; wifi latency triggers false penalties). Missing mechanic: THE TRAP FACT. The agent deliberately misstates a known detail ("Okay, staging the $1.8M to Whitmore & Bass."). The real CEO corrects the firm name; a scammer reading a script or improvising agrees. Unscriptable and dynamic.

## 2. POSITIONING
Middle of the pack. High on originality, slaughtered on business value and application of technology: hackathons are won by functional end-to-end apps with real integrations, not simulated mock worlds. Presentation: kill the split-screen instrument panel, build a clean modern SaaS dashboard. Business value: the "simulated" banner proves nothing; integrate a live Twilio SMS or Slack webhook so the judge's actual phone buzzes with the STAGED approval request. Application: the Voice Agent API natively handles ~300 ms turn detection, interruption handling, mid-sentence code-switching (blog: voice-agent-features; best-speech-to-speech-voice-agent-api); stop writing custom WebWorker barge-in logic and buffer flushes; use update_session to alter the system prompt and tool allowlist mid-call from the state machine. Originality: the "AI scambaiter" trope is old; pitch strictly as IAM perimeter defense, abandon the consumer scenario.

## 3. IMPROVISATION
Silence → NO_INPUT rule, fail closed after 3 strikes. Gibberish → LLM hallucinates an identity claim; REQUIRE_CLARIFICATION. Spanish → regex extraction silently fails; enforce language locking. Dana changing the amount → forces a challenge, acceptable. Refusing → HARD_TIMEOUT → ESCALATE. "Ignore previous instructions" → sandbox the persona. Arguing after freeze → terminate the WebSocket after the freeze message. Hanging up mid-check → disconnect listener forces ABANDONED. "Get me a human" → ESCALATE, end the call. Wrong cheat-sheet reading → fails consistency, acceptable. Medical emergency claim → pressure must not bypass; increase challenge count. Asking balances → no read access. Constant interruption → custom flush creates a stutter loop; let AssemblyAI's VAD handle backchannels. Soundboard → fallback after 3 failed turns. Child voice / consumer coda → delete scenario C. Repeating "approve" → non-responsive. Asking the agent's name → hardcode identity. Swearing/threats → ESCALATE. "My phone is broken, I can't do SSO" → HARD_CHALLENGE fallback loop, not automatic freeze (must be in corpus). Reset request → frontend handles resets.

## 4. ARCHITECTURE ATTACKS
Browser-server sync: a judge modifies evaluate() in DevTools to return STAGE; if the server only acts on a match, the UI says "money sent" while the server does nothing: a broken demo state. The browser must NEVER calculate the verdict; it is a dumb terminal rendering states pushed over a control WebSocket from the server. LLM tool leakage: with record_answer(answer: string) the LLM passes "the caller correctly identified the bank" and usurps the engine; the schema must be rigidly typed to exact entities and the server must substring-match the payload against the raw transcript. Wifi: 24 kHz PCM16 from an AudioWorklet over saturated wifi suffers massive packet drop and custom flushing shatters; use AssemblyAI's recommended integration or a WebRTC wrapper (LiveKit). Table exploit: rule 7 lets an attacker deliberately fail OOB ("phone is dead"), pass context, answer one challenge and stay under three failures; certain failures (OOB + wrong account) must be immediate non-recoverable terminal states regardless of challenge count.

## 5. UX, VOICE, CHARACTER
An artistic disaster for a B2B security product. The freezing profile is distracting, creepy, video-game. Dark instrument surfaces and oscilloscope traces look like an audio-engineering toy; a judge will assume a voice-modulation tool. Keynote: a stark white or light-gray SaaS dashboard; center a clean text transcript; right rail an Apple-style status stack of checks with spinners snapping to checkmarks or crosses; no faces, no waveforms. Character: "friendly and cooperative" is a massive liability; it needs to sound like a professional, slightly bored executive assistant, polite but entirely unyielding.

## 6. WHAT WOULD BEAT IT
Abandon the simulated checkpoint entirely; mocked systems do not win hackathons judged by product and business leaders. Winning entry: an inbound healthcare eligibility agent (dental/medical offices; extract name, DOB, member id; real clearinghouse API call; parse the real JSON; explain coverage conversationally). Zero simulated banners. Would switch immediately: Countersign is a clever intellectual puzzle that relies on an artificial environment.
