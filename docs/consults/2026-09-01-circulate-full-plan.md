2. The concept. Countersign: a conversational security checkpoint that stands between social engineering and irreversible actions. When a high-risk request arrives by voice (an urgent wire transfer at a corporate payment desk, a privileged credential reset), Countersign answers first. It runs a calm, adaptive spoken interrogation while a deterministic policy engine accumulates structured evidence and computes the verdict. Verified requests are only ever STAGED for an independent human second approval; voice alone never releases a transfer. Failed requests are FROZEN, an incident is opened, the real principal is alerted, and the caller is kept engaged (containment) while a hash-chained evidence record is exported. Tagline: "Countersign doesn't guess who's calling. It makes them prove it." The name means both the password a sentry demands and the second signature that makes a payment valid.

3. Settled honesty constraints (do not relitigate; attack everything else). (a) The product never claims to detect synthetic or cloned voices; the mechanism is behavioral verification only: what the caller knows, whether their story holds across turns, and what independent out-of-band checks say. (b) No voice biometrics of any kind. (c) The LLM never emits a verdict; a finite-state policy engine does, from typed evidence. (d) Evidence quotes verbatim speech-to-text substrings, never LLM paraphrase; raw facts are stored separately from interpretation. (e) All identities, companies and systems are synthetic and disclosed; SSO, out-of-band and payment systems are mocks behind a visible "simulated" banner. (f) The "policy engine decides, not the LLM" pattern is cited as published prior art (the APort Vault CTF: social engineering 74.6% success against model-only defenses, 0% against a policy engine); the claimed novelty is the assembled application to inbound voice fraud, never "first ever."

6. Architecture. TypeScript end to end. Browser (Vite + React split screen) connects DIRECTLY to AssemblyAI's Voice Agent API over WebSocket using a single-use ephemeral token minted by a small Node server (token endpoint sets a hard maximum session length that AssemblyAI itself enforces). Audio is 24 kHz PCM16 mono via an AudioWorklet; the socket and audio buffers live in a Web Worker; UI updates are throttled to about 15 frames per second. Barge-in: on the "speech started" and "reply interrupted" events the client flushes its playback queue immediately; the agent's transcript line comes back marked interrupted and trimmed to what the caller actually heard. The policy engine is a pure, dependency-free module: evaluate(conversation_log, tool_log, call_metadata, seed) returns state, verdict, evidence cards, reasons, per-state tool allowlist, and a phrasing goal for the LLM. It runs in the browser for conversational tempo and is RE-RUN on the server over the submitted logs before any terminal action (stage or freeze); the server acts only if its verdict matches the browser's, and the screen shows both verdicts side by side ("countersigned"). The LLM (selected through AssemblyAI's gateway; Claude class) only phrases within the current state's goal and may only call the tools on that state's allowlist; out-of-state tool calls are ignored server-side. No database: seed JSON and in-memory session state. Hosting: one small always-on container (Render Starter class) so a judge's first click never hits a cold start. Tests: Vitest replays recorded transcripts through the real engine in CI; the live API is never called in tests.

7. The engine in detail. States: INTAKE, CLAIM, CHALLENGE, EVIDENCE, CONSISTENCY_CHECK, DECISION, ACTION, SEALED, plus an OUT_OF_SCOPE state for a judge who says "I'm not the CEO, I'm testing this" (the agent explains itself, offers the two roles, nothing moves; never a deadlock). Evidence cards: identity claim, request parameters, knowledge check result, consistency flag (with BOTH verbatim quotes attached), SSO context result, out-of-band result, context check result (is this vendor and amount known in request history), pressure marker, out-of-scope marker. Extraction of amounts, claimed names, pressure phrases and out-of-scope phrases is deterministic code over the transcript; knowledge answers are recorded by the LLM via a typed tool whose quote is validated in code to be a verbatim substring (repaired to the last caller utterance if not). Published decision table, first match wins: (1) out-of-scope marker after the last identity claim, no action; (2) missing identity or request, keep eliciting; (3) any of SSO, out-of-band, context still pending, no decision yet; (4) FREEZE if out-of-band no-response AND SSO location mismatch, or a consistency failure AND any failed check, or three or more independent failures; (5) if the context check failed, at least one knowledge challenge is required before deciding; (6) zero failures, STAGE for second approval (pressure alone never blocks staging); (7) one or two failures with challenges remaining, ask another challenge; (8) otherwise ESCALATE to a human callback with nothing moved. Depth upgrades planned: a story ledger tracking every stated fact across turns (amount, bank, counsel, deadline, who approved, who else knows) with every restatement compared to the first; adaptive challenge selection driven by what the caller already claimed (names a bank, ask the account; claims an NDA, ask who signed); timing-based behavioral signals from transcript timestamps (seconds to answer a challenge, talk-over count, repeated demands), labeled as behavior, never identity; a stalling library of at least eight hold-the-floor lines mapped to check types, fired inside 300 ms so async checks never leave dead air; a replayable adversarial corpus of 20 to 30 recorded live human attack calls (pressure, flattery, partial knowledge, authority claims, interruption spam, story drift) shipped in the repo with the engine's verdicts.

9. Voice and character. The agent is friendly and cooperative, never showing its hand, sounding like it is helping the request along; for the honest caller that is good service, for the attacker it is containment; the only moment the mask drops is the verdict line, and it stays calm. Not a therapist persona. Agent rules for live overlap: yield to short overlaps and backchannels; retake the floor only after a pressure interruption (the one hard stop); never leave silence. Turn detection tuned so complete spoken amounts and account numbers are not cut off. Latency is published as measured p50/p95 from the real stack; the phrase "sub-second" is banned.

10. Positioning lines the entry intends to use. Every other entry uses voice as an interface; this one uses the conversation as an evidence instrument and the agent's own speech behavior as security controls (cross-turn consistency as evidence, barge-in as a control, stalling as latency defense, containment, the transcript as the record). Liveness and challenge-response systems ask "is this voice a machine?" and are useless against a live human impostor; Countersign asks "is this request true?", which stops the clone and the human con artist identically. The public reference wire-transfer voice-agent demo from a major GPU vendor exposes wire-execution tools to the agent; Countersign is built on the opposite promise. Business framing: identity governance for the deepfake era; the $25M video-call wire fraud and the 2026 vishing wave against major funds as the hook; cost per screened call versus average loss, all numbers labeled.
